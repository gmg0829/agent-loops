# 协商循环

## Purpose
多 agent 围议题提议、批评、收敛到结论的决策循环（roundtable）。
当用户说"开一轮 roundtable"、"这个议题吵一下"或幕僚长判断某需求分歧大时，用本 skill。
完整版 spec：`../specs/ROUNDTABLE_LOOP_SPEC.md`（v1.0）。
只做决策、不执行；执行走 dev loop / bug-fix loop。

## 形状
议题输入 → 幕僚长定议程+点名 → 背对背独立提议 → 交叉批评 → 收敛 → 僵持升级 → 纪要

## 开议条件
议题必须写成"选 A 还是 B"式的明确决策目标 + 背景材料。无决策目标 → 主持打回重写。
适用：方案选型、需求评审、复盘。不适用：执行、纯同步、闲聊。

## 角色
幕僚长主持（定议程、控场、写纪要）；PM 业务视角；Engineer 可行性；QA 专职挑刺（魔鬼代言人）；tinkabot 生态视角。

## 流程
1. 背对背提议：各自独立写，不许先看别人的，防锚定。格式：方案 + 理由 + 风险 + 成本。
2. 交叉批评：每人至少挑其他方案一个实质问题，具体到条；只说好话算弃权，重写。
3. 收敛三档：能合并就合并；合并不了打分（成本/风险/收益）或投票；平票僵持升级仲裁。
4. 轮次上限 3 轮，超了升级，不许扯皮。
5. 纪要：结论 + 分歧点 + 被否方案及原因，存档备查。

## 人的介入（仅两处）
僵持仲裁、最终拍板。

## 失败处理
议题不合格打回重写；bot 不交提议催一次再缺席进行；3 轮不收敛升级；批评放水点名重写。
