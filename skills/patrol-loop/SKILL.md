# 巡逻循环

## Purpose
高频 + 有记忆的常驻巡检：每 15 分钟扫一遍责任面，异常轻处置或升级，正常静默。
对标 pstack `/loop` 思想。用密 cron + 状态文件模拟常驻（VM 重置杀进程，真常驻不可靠）。
完整版 spec：`../specs/PATROL_LOOP_SPEC.md`（v1.0）。

## 每轮五步
读上次状态 → 扫责任面 → 对比变化 → 处置/上报 → 写回状态。
状态文件：`~/workspace/team/hidden_files/patrol-state.json`；日志：`~/workspace/team/hidden_files/patrol-log.md`。

## 责任面
1. 团队看板 BOARD.md：阻塞 > 24h → 升级；needs-info > 48h → 升级；状态 > 72h 未变 → 提醒 owner。
2. loop 健康：bug/dev loop 卡住或迭代超限未升级的单 → 升级。
3. cron 健康：同一任务连续 2 轮失败 → 上报；关键产出（晨报/精选/日报）缺失 → 上报。
4. 飞书 bot 存活：进程不在 → 尝试拉起；token 403 持续 → 上报一次，不再试。
5. 情报源健康：同一源连续 2 轮失败 → 上报并标记。

## 处置三档
- 自修：重启 responder、按各任务第 6 步规则重跑失败轮次 → 记日志，不打扰。
- 升级：修不了的按 §5 上报。
- 记录：纯信息记日志。无问题静默。

## 去重纪律
同一问题未解决前每轮只报一次；状态变化（恶化/恢复）才再报。

## 边界
只发现 + 轻处置 + 上报，不替 specialist 干重活，不碰对外动作。
替代 team-audit-3am；收编飞书看门狗（不再单建）；不重复各任务第 6 步的重试。
