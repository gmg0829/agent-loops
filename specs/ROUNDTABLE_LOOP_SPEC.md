# 协商循环 Spec（v1.0）

> 来源：2026-10-15 用户确认的协商型 loop 描述。
> 状态：v1.0。

## 1. 目标与非目标

- 目标：多 agent 围着议题提议、批评、收敛到结论，人只在僵持时仲裁、最后拍板。
- 非目标：不执行（执行走 pipeline loop）；议题必须有明确决策目标，不开闲聊会。

## 2. 形状

```
议题输入 → 幕僚长定议程+点名 → 背对背独立提议 → 交叉批评 → 收敛 → 僵持升级 → 纪要
```

## 3. 适用与不适用

- 适用：方案选型、需求评审（cut 定稿前挑刺）、复盘、有分歧的拍板议题。
- 不适用：执行类任务、纯信息同步、无决策目标的讨论。

## 4. 角色

| 角色 | 担当 | 职责 |
|---|---|---|
| 主持 | 幕僚长 | 定议程、点名参会、控场、写纪要 |
| 业务视角 | PM bot | 业务价值、优先级 |
| 可行性 | Engineer Bot | 技术可行、成本 |
| 挑刺 | QA bot | 专职魔鬼代言人，找风险 |
| 生态视角 | tinkabot | 工具/生态/可复用性 |

## 5. 流程 Spec

1. 输入：议题（写成"选 A 还是 B"式的明确决策目标）+ 背景材料。触发：他点名开，或幕僚长判断某需求分歧大值得开一轮。
2. 背对背提议：各参会 bot 独立写方案，不许先看别人的，防锚定。提议格式：方案 + 理由 + 风险 + 成本。
3. 交叉批评：每人至少挑其他方案一个实质问题，具体到条。只说好话算弃权，主持点名重写。
4. 收敛三档：
   - 能合并 → 合成一个方案；
   - 合并不了 → 按标准打分（成本 / 风险 / 收益）或投票；
   - 平票 / 僵持 → 升级给他仲裁。
5. 轮次上限：3 轮收敛不了 → 升级，不许无限扯皮。
6. 纪要：结论 + 分歧点 + 被否方案及原因。纪要存档，下次同类议题先查纪要，不重吵。

## 6. 人的介入点（仅两处）

- 僵持仲裁
- 最终拍板

## 7. 与 pipeline loop 的关系

- 协商只做决策、不执行。顺序：roundtable 定方案 → dev loop 执行。
- dev loop 外环分歧澄不清 → 开一轮 roundtable → 回去继续。

## 8. 失败处理

| 场景 | 处理 |
|---|---|
| 议题无明确决策目标 | 主持打回，改写成"选 A 还是 B"再开 |
| 某 bot 未按时交提议 | 催一次，仍不交则缺席进行（记一笔） |
| 3 轮未收敛 | 升级仲裁 |
| 批评轮放水 | 主持点名重写 |

## 9. 可观测性

- 每轮留：议题、提议原文、批评记录、收敛过程、纪要。
- 指标：开议题数、平均收敛轮次、升级仲裁率、纪要复用率。
