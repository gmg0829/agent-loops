# 打磨循环 Spec（v1.0）

> 来源：2026-10-15 用户确认的打磨型 loop 描述。
> 状态：v1.0。

## 1. 目标与非目标

- 目标：把一份产出物经「生成 → 评判 → 修正」闭环磨到成文标准，有明确退出条件。
- 非目标：不管排期、分诊、发布；没有成文标准不开磨。

## 2. 形状

```
初版产出 → 按标准评判 → 达标？→ 是：通过，进下一环
                        → 否：带评判意见回炉（计数+1）→ 超 N 次 → 升级给人
```

## 3. 适用场景

- 代码：写 → fuzz/review → 改（bug / dev loop 内环）
- 文档/报告：写 → 审 → 改
- X 帖子：写 → 过「有意义」标准 → 改
- QA 验收：修 → 验 → 回修
- 独立调用：「这篇稿子打磨两轮」

## 4. 五条硬规则

1. 标准前置且可执行：检查表 / 打分线，禁止「写好一点」类含糊表述。
2. 写判分离：生成者不评判自己，至少是不同角色。
3. 打回带意见：指哪条不行、怎么改，否则不许打回。
4. 退出三选一：达标通过 / 超 N 次（默认 3）升级 / 人工叫停。
5. 升级带记录：附历次评判意见与修改 diff。

## 5. 标准库（示例）

- 代码：fuzz 干净（10 分钟 / 1 万次零 crash）+ CI 绿 + diff 行覆盖 100%
- X 帖子：「有意义」标准（读者多知道一件事或多一个能用的东西）+ ≤280 字符 + 口径纪律
- 文档：结论先行 + 数据可溯源 + 一页纸摘要
- QA 验收：AC 全过（dev loop）/ fuzz 干净（bug loop）

## 6. 与其他 loop 的关系

- 通常嵌在 pipeline 里作子循环，也可独立调用。
- pass^k 是变体：评判加了连续性要求（连续 k 次通过才算过）。

## 7. 失败处理

| 场景 | 处理 |
|---|---|
| 无成文标准 | 不开磨，打回先定标准 |
| 写判同一人 | 评判无效，打回重判 |
| 打回无意见 | 打回无效，退回评判方补意见 |
| 超 3 次未达标 | 升级给人，附全记录 |
| 人工叫停 | 停，记原因 |

## 8. 可观测性

- 每轮留：产出版本、评判意见、修改点、计数。
- 指标：平均打磨轮次、一次通过率、升级率。
